title: Self-maintaining content engine and the internationalization foundation
scope: site
---

- Page registry: every address the site serves — 126 routes, including generated docs, spec, playground, alias, machine and locale pages — has a stable ID, kind, ownership class, maturity, navigation surface and search, LLM and sitemap flags in `src/content-engine/registry/pages.json`, the single route authority. The flags are checked against the built search index, `llms.txt` and `sitemap.xml` in both directions.
- Source registry and lock: 19 sources (protocol snapshot, ecosystem catalogue and GitHub facts, support details, Wintage palettes, docs, blog, fonts and more) are described with their canonical location, snapshot paths, refresh and validation commands; `source-lock.json` records the identity each build represents.
- Impact graph: `npm run site:impact` answers what a change to any source, page, block or document affects — pages, locale variants, translation units and the gates to run. `npm run site:doctor` reports sources, content, translations and derived outputs, proves itself with red controls, and runs in CI.
- Normalized models: pages read protocol, ecosystem, support and version facts only through `src/content-engine/models/`. GitHub release facts that were hand-copied into the ecosystem catalogue now come only from the synced snapshot; disagreement fails the build.
- Content blocks and locales: the words of the home, about, pricing, search and 404 pages, the shell and the docs chrome live in block catalogues with content hashes, rendered through a translator with an explicit fallback chain. Locales are data; locale routes, Markdown twins, a per-locale search index and `llms.txt`, `hreflang` alternates and a language selector are built from one variant plan.
- Translation workflow: `npm run i18n:status`, `i18n:export`, `i18n:import`, `i18n:validate`, `i18n:memory`, `i18n:add` and `i18n:enable`, a glossary of protected terms, glyph coverage of the pixel fonts, and a translator guide. Estonian and Russian are registered and wait for translation; an internal pseudo-locale proves routing, fallback, glyph coverage and layout stretch on every build.
- Maintenance commands: `site:sync` refreshes upstream snapshots safely (last valid snapshot kept, date-only churn dropped), `site:drift` prepares a SAIPEN ticket for meaningful drift, `site:affected` selects the gates a change needs, and `/debug/content/` shows content health. The community page is the first page composed from a manifest.
- Segmented documentation translation: a documentation page is no longer one translation unit. Every page is split into stable segments (its title, its description and each section) with explicit, permanent IDs — `docs.getting-started.introduction.what-persists` — so editing one paragraph marks exactly that segment stale in each locale instead of the whole page. A locale stores one entry per segment ID, a page falls back to English per segment with `lang="en"` on exactly the untranslated parts, the impact graph treats a segment as a first-class unit, `site:doctor` counts segments alongside UI blocks, and `i18n:export` hands a translator one bounded unit with its neighbouring segments for context — never a whole document.
- Complete code-face coverage: the pixel face for code no longer falls back to a system font. SAI Pixel Mono 12 stays a Spleen 6x12 design, and the code points Spleen does not map — typographic dashes, ellipsis and quotes, arrows, Latin Extended-A/B, the rest of the Cyrillic block, the full box-drawing set — are supplemented from DejaVu Sans Mono 2.37 on the same 6x12 grid by a pinned, licence-checked build step that fails when an approved source cannot draw a required character. The generated coverage metadata records the code face separately from translated prose (its own contract), and the pixel gate now proves the composite face itself, character by character. Translatable prose that had been styled as code moved to the proportional face, and the pseudo-locale keeps inline and fenced code verbatim even when a code span wraps across lines.
- Fixes: the About banner and long inline code no longer overflow a 320 px screen; blog posts of the same date have a stable order; the protocol snapshot check no longer fails on a Windows checkout that converts line endings.
